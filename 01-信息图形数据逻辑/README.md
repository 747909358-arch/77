# 01 信息图形数据逻辑

本目录定义信息图形的底层组织逻辑。这里不保存图片案例或案例数据集；所有案例均通过相对链接指向 [02-信息图形类型案例](../02-信息图形类型案例/README.md)。案例图片、分析记录和可获得的基础数据集统一保存在 02。

## 五类逻辑

1. [编年型信息图形概念定义](./01-编年型信息图形概念定义.md)（T）
2. [层级型信息图形概念定义](./02-层级型信息图形概念定义.md)（H）
3. [编目型信息图形概念定义](./03-编目型信息图形概念定义.md)（C）
4. [字母表型信息图形概念定义](./04-字母表型信息图形概念定义.md)（A）
5. [地理图形信息图形概念定义](./05-地理图形信息图形概念定义.md)（G）

五类是本仓库既定的一级分类。每张新图必须先依据整体主导的信息组织逻辑归入其中一类，再选择仓库已有的细分标签；混合案例须说明主类别、次要类型和判断依据。不得擅自新增一级类别。T/H/C/A/G 是类别识别代码，不应在缺乏标签清单依据时被当作完整的细分标签体系。

## 每张图的固定分析顺序

1. **01 五大类别归类**：判断主类别，记录次要/混合类型及理由。
2. **02 现有标签归类**：使用仓库已有标签并说明理由；若标签清单不可核实，标注待确认，不创造标签。
3. **图形特性**：分析信息目标、受众、结构、布局、构图、风格、色彩、字体、层级、密度和适用场景。
4. **制作方法与流程**：梳理数据采集、清洗、组织、计算、图形选择、编码映射、版面搭建、校验和输出；事实与推测分开标记。
5. **视觉编码**：提炼位置、长度、角度、面积、颜色、形状、方向、纹理、连接、空间位置、尺度、文字和符号等变量，以及字段映射和潜在误读。
6. **视觉叙事**：总结主题、阅读路径、信息揭示顺序、对比/转折、视觉焦点、叙事节奏和结论传达。
7. **写回案例库**：完整分析写入 02 对应案例目录的 `analysis.md`，并维护类型索引与本目录的相对链接。
8. **基础数据集入库**：可获得且许可允许的数据上传到对应案例目录的 `data/`，记录来源、字段、格式、处理步骤及编码映射；不可获得或不可再分发时如实标注，不得编造或上传受限数据。

## 共同分析维度

每一类型均从 A 数据逻辑、B 统计图形与计算方式、C 视觉编码、D 数据/信息架构、E 视觉叙事架构五方面分析，并注明适用条件、边界和反例。具体案例还必须补充图形特性、制作方法与流程、基础数据集状态。

> 理论定义、客观观察、分析推断应明确区分。稳定原则需由多个案例支持或有明确理论依据；单一案例的独特做法标记为“个案策略”。不将推断冒充案例观察。
