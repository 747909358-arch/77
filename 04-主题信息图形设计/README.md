# 04 主题信息图形设计

本目录是信息图形研究库的**主题项目实践层**。它调用 01 的信息组织逻辑、02 的案例与视觉方法标签、03 的统计图形知识，围绕一个具体主题完成从调研到设计实施的完整项目。

它与前三个目录的分工：

- **01 方法层**：信息应如何组织（T/H/C/A/G）。
- **02 案例层**：真实作品如何组织信息、使用视觉语言；保存案例与标签。
- **03 统计层**：统计数据如何计算、选择图形并表达。
- **04 项目层**：将前三者用于一个具体主题，形成可复查、可复现的设计成果。

## 项目目录命名

每个主题建立独立项目目录：

`项目-YYYYMMDD-主题简称`

项目内按以下阶段组织：

1. 前期调研
2. 主题内容分析（与大模型协作）
3. 数据搜集
4. 基础数据集构建
5. 叙事框架搭建
6. 视觉编码与风格系统
7. 信息轮盘测试
8. 设计实施与交付

## 项目工作流

| 阶段 | 核心问题 | 主要产出 |
|---|---|---|
| 01 前期调研 | 为什么做、给谁看、要回答什么？ | brief、受众、问题、来源地图 |
| 02 主题内容分析 | 主题由哪些概念、对象、事件和关系构成？ | 概念树、内容清单、主类别与标签建议 |
| 03 数据搜集 | 哪些公开数据、文本文献和自建资料可用？ | 来源登记表、原始资料、许可记录 |
| 04 基础数据集构建 | 如何把资料转成可分析的数据？ | 单列原子数据、结构化多字段数据、数据字典 |
| 05 叙事框架搭建 | 数据如何组合成明确的主题叙事？ | 叙事主张、章节顺序、字段关系图 |
| 06 视觉编码 | 数据映射到哪些视觉通道与图形语言？ | 编码映射表、风格板、草图 |
| 07 信息轮盘测试 | 信息是否准确、易读、可理解？ | 测试记录、问题清单、修改决策 |
| 08 设计实施 | 如何完成、校验和交付？ | 最终作品、源文件、数据与版本记录 |

## 新项目的基本原则

- 先明确内容与数据，再选择视觉风格；不要先决定“做成照片风格/词云”再硬套资料。
- 主类别从 T/H/C/A/G 中判断；ISOTYPE、照片型、词云等属于视觉方法或表现标签，不新增主类别。
- 单列数据集阶段坚持“一行一个观测值/条目”的原子记录原则；一列只承载一个定义明确的变量，不能把多个含义塞进同一单元格。
- 叙事数据集可以有多列，但每列必须有字段定义，列与列之间应形成可解释的关系。
- 任何数据均需记录来源、许可、时间范围、口径、单位、清洗过程和不确定性。
- 大模型用于协助拆解主题、提出分类候选、检查逻辑和生成研究问题；事实、数字和来源必须回到原始资料核验。
- 信息轮盘测试是项目内的检查环节，不预设具体测试模型；每次测试需记录参与者、任务、观察和修改结果。
