# 参考身份与观察程序

## 1. 参考身份六角色

| role | 使用范围 |
|---|---|
| `style_reference` | 识别视觉语言与风格关系 |
| `content_reference` | 保持主体身份、形态、产品结构或指定内容 |
| `layout_reference` | 保持或分析布局、图文关系、阅读顺序 |
| `system_diagram` | 理解系统结构，不复制说明图自身的美术样式 |
| `current_output` | 指定修订和审查对象，不自动视为新基准 |
| `task_brief` | 用户文字要求、限制和交付条件 |

一份材料可有多重用途，但须分别注明范围。系统说明图不能代替真实风格样图；内容参考不自动决定全部配色和表现方式。

## 2. 观察程序

1. 确认实际可查看的文件、图像和版本。
2. 先整体后局部；多图先逐张记录，再归纳共同条件、条件变体和冲突。
3. 不将所有元素取并集，也不把不同画法简单平均。
4. 单图只支持作品级档案，不直接代表整个画家、画派或时期。
5. 每项判断标记 `observation`、`inference`、`user_requirement` 或 `design_choice`。
6. 记录证据来源；无法查看或无法判断时标记 pending/unknown，不猜测。

## 3. 从观察形成核心

判断链：可见特征 → 在整体中的作用 → 是否承担身份识别 → 适用条件 → 可变边界 → 检查方法。

复核问题：更换具体对象后，关系能否继续成立？改变这条关系后，风格身份是否仍成立？

## 4. 推荐分析顺序

整体视觉世界与叙事立场 → 主要空间和注意力结构 → 色彩与光线 → 造型/线条/边缘 → 完成度和材质 → 信息密度/锚点/张力 → 独特视觉异常。

不得只输出“高级、唯美、复古、温柔”等感受词；必须转译成可观察、可描述、可核验的视觉关系。
