# 图像模型后端适配

## 1. 通用原则

- 先定义叙事与任务，再选工具。
- JSON 不是通用图像 API；通常需要转译成后端接受的自然语言或结构化接口。
- 记录实际后端名称、可得版本、参考输入、能力、尺寸、种子（若可得）和真实提交指令。
- 无法取得的值写 `null`；能力未查明写 `unknown`。
- 同一提示词、同一结构、同一种子不保证跨后端像素复现。
- 不推断当前模型能力；上线前按实际产品版本重新核验。

## 2. 后端能力自查

- 是否接受 JSON，还是需转译自然语言？
- 是否支持参考图或图像编辑？
- 是否支持精确权重或种子？
- 文字渲染能力如何？
- 多图/角色一致性能力如何？
- 是否有独立负向提示接口？
- 哪些字段敏感或较弱？

## 3. 适配记录

每次生成保存 `backend_id`、模型/版本（如可得）、输入模式、参考图、实际提交文本、输出规格、能力未知项和测试状态。不得把旧文档中的模型能力描述直接当成当前版本的保证。
