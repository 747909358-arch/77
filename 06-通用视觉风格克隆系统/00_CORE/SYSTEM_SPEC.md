# 系统总规范

## 1. 系统定位

风格克隆对象是**具有识别作用的视觉特征及其组织关系**，不是原图中的人物、器物、背景或文字清单。系统将参考分析转化为可表达、可关联修改、可重新调用的生成条件。

完整链路：

`参考依据 → 风格分析 → 核心识别 → 规则组织 → 主题适配 → 提示词编译 → 实际生成 → 结果审查 → 有范围的修订`

## 2. 六条总原则

1. 先理解，再表达：先做语义与形式分析，再选择字段措辞。
2. 特征与关系一起提取：不仅写特征是什么，也写它们如何组织空间、注意力和叙事。
3. 风格与内容分开记录，适配时重连。
4. 固定项必须说明依据：区分风格核心与本项目锁定项。
5. 主题改变要检查关联条件，不能机械替换名词。
6. 以实际结果验收：规则写对、JSON 合法、模型声称完成，都不能替代图像检查。

## 3. 四种工作模式

- `extract`：从参考提取风格，建立档案。
- `apply`：调用档案适配新主题，交付提示词或按明确要求生成图像。
- `revise`：针对指定作品做有边界修改。
- `audit`：审查参考分析、档案、提示词或输出。

## 4. 架构

一个核心风格基因、五个总控、十三个分系统：

- A 美学定位：A1 风格本体。
- B 视觉形式：B1 色彩、B2 光线、B3 空间构图、B4 尺度关系。
- C 绘画表现：C1 绘画语言、C2 边缘控制、C3 完成度控制、C4 材质与纹理。
- D 内容生成：D1 主体设计。
- E 视觉控制：E1 信息密度、E2 视觉锚点、E3 视觉张力。

五个总控是职责分类，不是五段独立提示词，也不是固定执行顺序。最终回到 A1 所规定的身份边界。

## 5. 三记录分离

- `style_profile`：可复用风格、来源、核心规则和版本。
- `image_task`：当前主题、项目锁定项、适配和执行条件。
- `image_review`：具体产物的检查、偏差和修订记录。

风格档案不得被一次主题污染；任务不得只写“沿用上次”；验收必须指向明确版本的实际产物。

## 6. 必须区分的概念

- 风格 vs 内容：提取时分开记录，适配时重新连接。
- 风格核心 vs 项目锁定：来源与作用不同。
- 视觉锚点 vs 风格一致性锚点：前者组织单图注意力，后者核验多图表现体系。
- 信息密度 vs 描绘精细度：前者是信息分布，后者是局部展开方式。
- 纹理 vs 造型：纹理不能代替形体建立。
- 文字未变 vs 图像区域未变：文本保护不能证明图像区域未变化。

## 7. 来源标记

每项结论区分：`observation`（观察）、`inference`（推断）、`user_requirement`（用户要求）、`design_choice`（设计选择）。不得将推断或设计选择倒写成参考图事实。
