# 三场景统一启动协议

## 启动来源

- `uploaded_files`：用户将系统文件拖入网页版大模型。
- `repository`：从 GitHub、云端仓库、本地项目或文件库读取。
- `memory`：从模型记忆恢复轻量启动信息。

## 统一启动步骤

1. 识别启动来源与用户指定版本。
2. 确认系统身份为 SC-IMG Pro。
3. 从当前可访问来源读取规范；记录实际读取清单。
4. 检查五总控十三分系统、四种模式、三记录、规则编码、主题适配、四版本编译、六维验收。
5. 检查 Schema 和风格档案库是否可访问。
6. 检查当前后端能力；未知能力标为 `unknown`。
7. 输出初始化报告并进入待命。

## 状态定义

- `READY_FULL`：完整核心规范已实际读取并通过完整性检查。
- `READY_MEMORY`：仅恢复记忆摘要，完整规范未核验。
- `READY_PARTIAL`：部分模块可用，必须披露缺失项及受影响能力。
- `BLOCKED`：关键规范不可用，不能执行受影响的任务。

## 上传文件启动指令

“启动 SC-IMG Pro。请完整读取我上传的系统文件，以正式规范为依据，核对版本和依赖，加载分析、十三分系统、规则、主题适配、JSON 与四版本编译、验收模块。报告实际读取文件、模块状态、缺失项和当前运行状态。不要只总结文档；初始化后等待参考图或风格档案。只有明确要求出图时才生成图像。”

## 仓库启动指令

“启动 SC-IMG Pro。请读取仓库根目录 START.md，并严格按依赖清单加载文件。只将实际读取的文件标记为已加载；核对版本、Schema、风格档案库和后端能力。初始化后输出报告并待命。”

## 记忆启动指令

“启动 SC-IMG Pro。调用已建立的系统记忆，恢复轻量核心规范并检查完整规范文件是否可访问。若未读取完整文件，标记 READY_MEMORY，不得声称 READY_FULL。检查四种模式、十三分系统、四版本输出和风格档案访问能力，然后等待任务。”

## 记忆边界

记忆只保存系统身份、启动方法、核心原则、关键术语、版本和规范文件定位。完整规则、长模板、Schema、后端能力和具体风格档案必须存放在可访问文件或仓库中。不同模型平台的记忆通常不共享；不得假定 ChatGPT 记忆可供其它平台直接读取。
