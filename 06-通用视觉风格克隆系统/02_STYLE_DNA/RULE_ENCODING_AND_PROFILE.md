# 风格 DNA、规则编码与档案

## 1. 核心风格基因

核心风格基因是在某一风格档案中，对身份识别起关键作用的“特征—关系集合”。核心不能只由重复出现或醒目程度决定；需排除共同素材、固定布局、拍摄条件等偶然相似。

## 2. 规则三维编码

每条规则必须记录三个维度：

- `requirement_type`: `style` / `content` / `presentation`
- `change_type`: `core` / `project_locked` / `conditional` / `free`
- `priority`: `must` / `should` / `may`

同一项可以是 content + project_locked + must。没有任何模块永久固定或永久可变；`must` 不是图像模型已实现的硬约束。

## 3. 规则标准句式

在〔条件〕下，〔对象/区域〕采用〔具体表现方式〕，与〔关联对象/区域〕形成〔关系〕，以保持〔识别作用/任务目的〕；允许改变〔范围〕；通过〔办法〕核验。

每条规则记录唯一 ID、模块、来源、作用对象、条件、依赖（requires）、冲突（excludes）和验收办法。相同要求只保留一个权威表述，其它模块引用规则 ID。

## 4. 核心与项目锁定

- 风格核心由参考与识别目标决定；项目锁定由本次用户要求决定。
- 颜色、构图、画幅、主体数量不天然是全局常数。
- 有意改变旧核心时建立派生档案，说明保留与改变；不能改变核心后仍声称原风格未变。
- 必须条件冲突时，先检查能否通过区域、主次、承担对象或执行方式重新组织；仍不相容则明确冲突，不静默删除。
- 可选项与必须项冲突时停用可选项并记录。

## 5. 三记录数据契约

### style_profile
保存可复用风格、参考来源、核心规则、五个一致性锚点、适用范围、版本和证据。

### image_task
保存本次主题、对象、动作、环境、叙事、项目锁定项、允许改变范围、画幅和输出要求。

### image_review
保存明确版本的实际图像、提示词、后端、六维验收、偏差证据、修订内容和状态。

## 6. 五个风格一致性锚点

- `line_quality`
- `color_palette`
- `light_logic`
- `space_treatment`
- `detail_density`

这五项用于多图风格一致性检查，不替代十三系统完整分析，也不等于单图视觉锚点。
