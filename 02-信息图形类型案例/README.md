# 02 信息图形类型案例

本目录保存案例图、出处、观察记录、分析结论及可获得的基础数据集。本目录是案例资产的唯一归档位置；[01-信息图形数据逻辑](../01-信息图形数据逻辑/README.md) 只通过文本链接引用案例，不重复保存图片或数据文件。

## 固定入库顺序（每张新图均执行）

### 01｜五大类别判断
先判断案例的主导信息组织逻辑，归入仓库既有五类之一：
- 编年型（T）
- 层级型（H）
- 编目型（C）
- 字母表型（A）
- 地理图形型（G）

若一张图包含多种结构，必须明确一个主类别，并在分析中记录次要/混合类型及判断依据；不得因为局部图表形式而误判整体类别。不得擅自新增第六类。

### 02｜现有标签判断
在完成五类归类后，再从仓库已经建立的标签体系中选择最匹配的标签，并记录标签及选择理由。类别代码 T/H/C/A/G 用于五大类别识别，不自动等同于全部细分标签。若仓库尚无可核实的细分标签清单，标注“待补充/待确认”，不得自行编造标签或将类别代码伪装成细分标签。

### 03｜案例特性分析
描述图形的核心特征，包括信息目标与读者、内容单元/字段、版面布局、构图、视觉风格、色彩、字体、图形语法、信息密度、阅读入口与适用场景。区分客观观察和分析推断。

### 04｜制作方法与工作流程
尽可能还原制作路径：数据/资料采集与清洗、字段整理、内容分组与排序、尺度/统计计算、图形选择与编码映射、版面搭建、视觉设计、校验与输出。记录可识别的工具、软件、代码或工作流；无法从图中确认的部分明确写“推测”或“未知”，不得把推测写成事实。

### 05｜视觉编码提炼
逐项分析位置、长度、角度、面积、体积、颜色、明度、形状、方向、纹理、连接、空间位置、尺度、文字/符号等视觉变量；说明每种变量对应的数据字段、表达关系、定量/定性属性、比较任务及可能产生的误读。

### 06｜视觉叙事提炼
总结叙事主题、信息组织逻辑、阅读路径（入口—展开—转折/对比—重点—结论）、视觉焦点、层级节奏、信息揭示顺序、情绪/修辞策略，以及图形如何支持或影响读者理解。

### 07｜归档与关联
每个案例建立独立子目录，命名为 `案例编号-简短名称`。分析完成后写入 `analysis.md`，并在类型索引及 01 理论文档中建立相对链接。保留来源和版权信息。

### 08｜基础数据集入库
只要能从原始来源、附件或用户提供材料中获得底层数据，就应将原始/基础数据文件一并上传到该案例目录的 `data/` 子目录，并在 `analysis.md` 记录文件名、格式、来源、字段说明、数据处理/清洗情况及与图中编码的对应关系。尽量保留原始版本；清洗版或转换版另存并说明处理步骤。若数据不可获得，明确写“未找到可公开/可用的基础数据集”，记录查找范围或原因，不得反向编造数据。涉及许可、隐私或再分发限制时，不上传受限数据，改存来源链接和限制说明。

## 案例目录建议结构

```text
案例编号-简短名称/
├── source.md       # 原始出处、作者/机构、标题、发布时间、访问日期、URL、版权/许可
├── analysis.md     # 完整案例分析
├── image/          # 原图及必要局部图（保留来源和文件名）
└── data/           # 可获得的基础数据集、数据字典及必要的处理说明
```

## 迭代规则

每新增案例，先完成类别与标签判断，再写客观观察和分析，最后归纳跨案例共性。只有被多个案例支持或有明确理论依据的内容才提升为稳定原则；单一案例的独特做法标记为“个案策略”。发生修订时，在相关类型文档的“版本记录”中说明依据，并同步更新 01 目录中的逻辑定义和双向链接。不得将推测冒充事实，不得编造来源、数据或制作流程。
