# 信息图形案例分析与入库规范

本规范适用于用户发来的每一张信息图、图表组合、数据插画或信息可视化作品。目标不仅是描述画面，而是沉淀可复用的数据组织方法、视觉编码方法、制作流程与视觉叙事策略。

## 一、固定判断顺序

### 01｜先判断五类信息图形归属（主分类）

每个案例必须先选定一个主分类；若作品确实跨类，可补充次分类，但不得跳过主分类。

| 类别 | 核心组织逻辑 | 判断依据 |
|---|---|---|
| 编年型 | 时间 + 事件 + 顺序 | 时间先后是主要阅读骨架，强调演变、阶段、持续时间或历史过程 |
| 层级型 | 上下位 / 包含 / 从属 | 信息由整体到局部、由高到低或按分类层级展开 |
| 编目型 | 对象集合 + 条目 + 属性 | 以对象、项目、样本或条目为核心，强调检索、比较、枚举与属性识别 |
| 字母表型 | 字母 / 符号序列 + 对应条目 | 以字母、字符或固定符号序列作为组织和导航框架 |
| 地理图形 | 地理位置 / 空间关系 | 地图、地形、区域、路径或地理邻接关系构成主要空间骨架 |

判定原则：依据作品的主导信息组织逻辑，而不是依据它“看起来像哪种图表”。混合图形应识别主叙事骨架，并记录辅助结构。

### 02｜再判断标签（次级检索标签）

- 标签用于描述具体图形形态、数据关系、主题对象、视觉手法或叙事方式，不替代五类主分类。
- 优先沿用仓库中已有案例标题、术语和标签用词，保持命名一致。
- 可为一个案例添加多个标签，建议按“图形形态 / 数据关系 / 视觉手法 / 主题领域”组织。
- 若现有标签无法准确覆盖，先标记“建议新增标签：xxx”，说明理由；不要为了归类而强行套用，也不要把新标签伪装成既有标签。
- 标签应具体、可检索、可复用，避免“好看”“高级”等主观评价词。

## 二、每张图的标准分析结构

### 1. 基本信息与来源
记录案例名称、原始出处/URL、作者或机构、发布时间（可查时）、图像文件名、收录日期及来源可信度。区分原始作品、转载图和二次编辑版本。

### 2. 01 主分类
写明五类中的主分类，并用一句话解释其核心组织逻辑；如有必要，补充次分类及混合结构说明。

### 3. 02 标签
列出沿用标签、建议新增标签（如有），并注明标签维度：图形形态、数据关系、视觉手法、主题领域。

### 4. 图形特性
从画面结构、阅读路径、信息密度、层级关系、模块组织、版式比例、色彩系统、字体与标注、图例/注释等方面描述可观察特征。把“观察事实”与“设计解释/推断”分开写。

### 5. 数据本质与信息架构
分析数据的方向性、顺序性、维度性、连续性、时空定位、关联性；判断信息架构属于线性、层级、节点、并行、分组、网络或混合结构。指出哪些数据字段支撑了哪些视觉关系。

### 6. 视觉编码（重点）
逐项说明数据变量如何映射到视觉通道：
- 位置与空间布局：横纵轴、径向、地图坐标、分区、节点位置；
- 长度、面积、角度、宽度、距离、方向、曲率等几何编码；
- 色相、明度、饱和度及其分类/顺序/强调含义；
- 形状、图标、纹理、线型、边框、大小；
- 文字、数字、标签、注释、图例与层级；
- 多变量如何组合编码，是否存在冗余编码；
- 编码是否准确、可比较、可读，是否可能造成误读。
对每种编码说明“承载的数据字段—视觉通道—读者获得的信息”。

### 7. 视觉叙事
提炼作品希望读者回答的核心问题；说明标题如何设定议题、信息如何排序、视觉焦点如何建立、阅读路径如何引导、对比/转折/高潮如何形成、结论如何被强调。总结其叙事模式（如时间演进、空间探索、分类检索、规模比较、因果解释、关系揭示等），并指出叙事取舍与信息缺口。

### 8. 制作方法与复现流程
尽可能从结果反推制作过程，并明确区分“图中可确认”与“合理推测”。至少记录：
1. 数据搜集与来源核验；
2. 数据清洗、字段定义、单位统一、缺失值处理；
3. 数据结构与表格组织；
4. 信息架构与主次关系设计；
5. 图形类型和视觉编码选择；
6. 版式、标注、配色、字体与图例设计；
7. 校验：数值准确性、比例/尺度、排序、可读性与无障碍；
8. 导出、发布与版本管理。
如无法确认具体软件，不要臆测软件名称；可写“可能的实现方式”并给出替代工具路径。

### 9. 可复用设计原则
提炼可迁移的设计技巧、适用数据条件、适用场景、局限、易错点，以及可用于下一张图的制作检查清单。

## 三、基础数据集归档规则

每个案例都应尽可能同时保存“图像 + 分析文档 + 基础数据集 + 来源记录”。

- 优先保存原始数据文件（CSV、XLSX、JSON、GeoJSON 等）及数据来源、许可/版权说明。
- 若原始数据无法取得，可根据图中明确可读的信息建立“人工转录数据集”，必须标记为转录/重建数据，不得称为原始数据；保留字段、单位、估读值标记和不确定性说明。
- 若只能提取部分数据，记录覆盖范围、缺失项和估读规则；不得补造数值。
- 数据文件应附字段说明（数据字典）：字段名、含义、类型、单位、来源、缺失值规则。
- 文件建议放在对应案例目录的 `data/` 子目录；图像放在案例目录，分析文档放在同一案例目录。
- 同时保存来源 URL、抓取/下载日期、作者/机构、许可信息；尊重版权与数据使用限制。无法合法再分发时，保存来源链接、数据字典和必要的可复现提取说明，不上传受限原始数据。
- 对用户提供的图像或数据，保留原始文件，不覆盖、不擅自修改；分析、清洗或重建数据另存为派生文件。

## 四、建议案例目录结构

```text
02-信息图形类型案例/
  案例-[分类代码]-[序号]-[名称]/
    README.md                 # 案例分析
    image/
      original.png            # 原始图像（按实际格式命名）
    data/
      source.csv              # 可合法归档的原始数据
      reconstructed.csv       # 无原始数据时的转录/重建数据
      data-dictionary.md      # 字段、单位、来源与缺失值说明
    source.md                 # 出处、作者、日期、许可与采集记录
```

目录与文件按实际可得材料创建；没有的数据不得创建空文件冒充已收录。

## 五、质量控制与迭代

- 事实、推断、建议分栏或显式标注；不能从图片确认的制作细节标为“推测/待验证”。
- 主分类必须来自上述五类；不确定时写明候选类别及判断依据，不武断定类。
- 新案例要链接对应分类方法文档；若案例揭示新规律，回写方法论文档并注明由哪个案例支持。
- 同一案例的图片、分析、数据和来源必须互相对应，文件名和案例编号一致。
- 每次入库检查是否有重复案例、是否沿用已有标签、数据是否可追溯、图表数值是否能复核。
- 不覆盖原始素材；修改分析时保留重要修订记录。
